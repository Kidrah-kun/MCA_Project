💡 Key Concepts Demonstrated

⚡
Cache HIT (1 cycle): When the CPU asked for data already in cache (valid=1 AND tag matches), it got the response instantly — no RAM access needed. This is why caches exist: to serve data at CPU speed.
🔄
Cache MISS (3+ cycles): When data wasn't in cache, the CPU was stalled (cpu_stall=1) while the cache controller fetched from DRAM. The 3-cycle latency simulates real DRAM slowness. After the miss, the data is cached so the next access is a HIT.
✏️
Write-Through Policy: Every write updated both the cache AND main memory simultaneously. This keeps memory consistent without dirty bits — simpler hardware, always-fresh RAM at the cost of more bus traffic.
⭐
D-Cache Priority Arbitration: When both caches missed at the same time (T1), the FSM controller served D-Cache first. Data hazards in the execution pipeline are more urgent than instruction fetch — serving D first minimizes pipeline stalls.
🏛️
Harvard Architecture: I-Cache and D-Cache are completely separate, so the CPU can fetch an instruction AND read/write data in the same clock cycle simultaneously — unlike Von Neumann where one shared bus means conflicts.
